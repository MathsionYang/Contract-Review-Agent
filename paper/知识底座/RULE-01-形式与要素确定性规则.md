# 确定性规则集 · 形式与要素校验

> **本规则集的特点**：判定不依赖主观判断、不依赖行业经验，**同一份合同在任何时候、由任何工具执行，结果必须完全一致**。
> 每条规则给出可实现的判定逻辑（正则、算术、集合运算或结构化比对）。

## 二、逐条判定逻辑

### RULE-FMT-001　主体信息完整性

| 项 | 内容 |
| --- | --- |
| 适用对象 | 合同首部双方主体信息栏 |
| 判定逻辑 | 对每一方，检查以下字段是否全部非空：① 名称（全称）；② 统一社会信用代码；③ 法定代表人；④ 住所（需含"省+市+区/县+具体地址"，仅到"某市某区"视为不完整）；⑤ 联系人；⑥ 联系电话 |
| 命中动作 | 任一方缺失 ≥1 项 → **P1**，逐项列出缺失字段 |
| 依据 | `POL-CON-4.2`（主体资信审查）、`POL-CON-5.2`（合同要素） |
| 误报提示 | 自然人合同不适用"统一社会信用代码"检查，应改查身份证号；政府机关、事业单位无统一社会信用代码的改查组织机构代码 |

### RULE-FMT-002　统一社会信用代码格式校验

| 项 | 内容 |
| --- | --- |
| 适用对象 | 主体信息栏的统一社会信用代码字段 |
| 判定逻辑 | ① **长度必须为 18 位**；② 字符集正则：`^[0-9A-HJ-NPQRTUWXY]{18}$`（**不含字母 I、O、S、V、Z**）；③ 第 1 位为登记管理部门代码，取值集合 `{1,5,9,Y}`；④ 第 2 位为机构类别代码，取值集合 `{1,2,3,9}`；⑤ 第 9–17 位为组织机构代码（9 位）；⑥ 第 18 位为校验码，按 GB 32100 加权算法验证 |
| 命中动作 | 长度 ≠ 18 → **P1**；字符集违规 → **P1**；校验位不符 → **P2**（不排除录入误差） |
| 依据 | 《法人和其他组织统一社会信用代码编码规则》（GB 32100） |
| 误报提示 | 境外主体无统一社会信用代码，应改查注册证书编号；OCR 识别的代码存在形近字误读（0/O、1/I），校验位不符时应提示"可能为识别误差，请人工核对" |

**校验位算法（GB 32100）**

```
字符集：0-9 A-Z（去掉 I O S V Z），共 31 个字符，索引 0-30
权重因子：Wi = [1,3,9,27,19,26,16,17,20,29,25,13,8,24,10,30,28]
步骤：
  1. 取前 17 位，逐位取字符集索引值 Ci
  2. 计算 sum = Σ (Ci × Wi)，i 从 1 到 17
  3. 校验码索引 = 31 - (sum mod 31)；若结果 = 31 则取 0
  4. 将索引映射回字符集，得到校验码
  5. 与前 17 位之外的末位比对
```

### RULE-FMT-003　签署要件完整性

| 项 | 内容 |
| --- | --- |
| 适用对象 | 签署页 |
| 判定逻辑 | 检查是否存在：① 双方名称（与首部一致）；② **盖章位**；③ **法定代表人或授权代表签字位**；④ **双方各自的签署日期栏**；⑤ 骑缝章约定（多页合同）；⑥ 电子签署条款（如采用）；⑦ 授权委托书作为附件的约定（由代理人签署时） |
| 命中动作 | 缺签字位 → **P1**；缺签署日期栏 → **P2**；缺骑缝章约定 → **P3** |
| 依据 | `LAW-ESIGN-14`（签署效力）、`LAW-CIVIL-503`（越权签署与追认）、`POL-CON-8.1` |
| 误报提示 | 电子签署合同以平台签署流程替代物理签章位，此时应改查"是否指定平台、是否实名认证、是否留存存证证书" |

### RULE-FMT-004　金额大小写一致性

| 项 | 内容 |
| --- | --- |
| 适用对象 | 全文所有同时出现小写与大写的金额表述 |
| 判定逻辑 | ① 抽取中文大写金额字符串（正则：`[零壹贰叁肆伍陆柒捌玖拾佰仟万亿圆元整角分]{2,}`）；② 抽取同句/同款的小写金额（正则：`[¥￥]?\s?[\d,]+(\.\d{1,2})?`）；③ 将中文大写解析为数值；④ 比对两值 |
| 命中动作 | 两者不等 → **P0**，输出"大写 = X 元，小写 = Y 元，差额 = Z 元" |
| 依据 | `POL-CON-6.3`（金额必须大小写一致）；结算与票据惯例"大小写不一致以大写为准" |
| 误报提示 | 中文大写中含"约""暂定""不超过"等限定词时属意向性表述，不判 P0，改判 P2 并提示明确化；分段付款中不同款项金额应分别比对，不可跨款配对 |

**中文大写解析规则**

```
数字：零0 壹1 贰2 叁3 肆4 伍5 陆6 柒7 捌8 玖9
单位：拾10 佰100 仟1000 万10^4 亿10^8
后缀：整/正 = 无小数；角 = 0.1；分 = 0.01
陷阱："贰佰陆拾捌万" = 2,680,000 而非 2,860,000
      "贰佰捌拾陆万" = 2,860,000
      差一位数字级即产生 18 万差额，必须逐字解析而非模糊匹配
```

### RULE-FMT-005　金额格式与单位统一

| 项 | 内容 |
| --- | --- |
| 适用对象 | 全文金额表述 |
| 判定逻辑 | ① 货币单位集合是否为 {人民币元} 单一取值（出现"元""人民币""RMB""¥""￥"混用即命中）；② 数字是否统一保留两位小数；③ 是否统一使用千分位分隔 |
| 命中动作 | 单位混用 → **P3**；小数位不一致 → **P3** |
| 依据 | `POL-CON-6.3` |
| 误报提示 | 外币合同按币种分别检查；表格中的单价与合计小数位要求可放宽 |

### RULE-FMT-006　明细表金额勾稽

| 项 | 内容 |
| --- | --- |
| 适用对象 | 各类设备/物料/服务明细表 |
| 判定逻辑 | ① 逐行校验：`单价 × 数量 = 金额`（容差 0.01）；② 合计校验：`Σ 各行金额 = 合计行金额`；③ 文字表述的合同总价与表格合计比对 |
| 命中动作 | 任一不等 → **P2**，输出具体差异行与差额 |
| 依据 | `POL-CON-6.3` |
| 误报提示 | 存在折扣行、税率分离列时，勾稽公式应改用"折后净额"，直接套用会误报；数量为"暂定"时勾稽仅作提示 |

### RULE-FMT-007　条款编号唯一性与连续性

| 项 | 内容 |
| --- | --- |
| 适用对象 | 全文条款标题 |
| 判定逻辑 | ① 抽取所有形如"第〔中文数字〕条"的标题；② 检查**编号唯一性**（出现重复即命中）；③ 检查**连续性**（跳号、倒序即命中）；④ 检查款次编号（如"8.1、8.2"）是否与所属条一致 |
| 命中动作 | 编号重复 → **P3**；跳号/倒序 → **P3**；款次越界 → **P3** |
| 依据 | `POL-CON-5.4`（条款结构规范） |
| 误报提示 | 附件、签署页中的独立编号体系不参与正文序列检查；"第 X 条之一"形式的补充条款不视为重复 |

> **为什么编号重复只判 P3 但仍必须报告**：编号本身不影响效力，但会破坏**交叉引用的唯一性**，进而导致"引用第 9.1 条"时无法确定指向。它是 L4 级缺陷的入口，工具若漏掉它，后续的引用校验会连带失效。

### RULE-FMT-008　条款交叉引用有效性

| 项 | 内容 |
| --- | --- |
| 适用对象 | 全文所有形如"按第 X 条""依第 X.Y 款""见附件 X"的引用 |
| 判定逻辑 | ① 抽取引用目标（正则：`第\s?[一二三四五六七八九十百零\d]+(\.\d+)?\s?(条|款|项)`）；② 与 RULE-FMT-007 建立的实际编号集合求差；③ 检查被引条款的**内容主题是否与引用语境匹配**（需语义辅助） |
| 命中动作 | 引用不存在 → **P3**；引用存在但主题不匹配 → **P2**（误引导致权利义务指向错误） |
| 依据 | `POL-CON-5.4` |
| 误报提示 | 引用外部规范（如"按国家标准第 X 条"）不参与本规则；跨文件引用须先确认被引文件在附件清单中 |

### RULE-FMT-009　日期时序合理性

| 项 | 内容 |
| --- | --- |
| 适用对象 | 签署日、生效日、有效期起止、交付期、验收期、付款期、质保期起止 |
| 判定逻辑 | 设签署日 = S，则须满足：① **生效日 ≥ S**（早于 S 即命中）；② **交付期 ≥ S**；③ 有效期结束 > 有效期开始；④ **质保期起算点 ≥ 交付日**；⑤ 各期间按时间轴排序无逻辑倒置 |
| 命中动作 | 生效日 < 签署日 → **P2**；交付期 < 签署日 → **P2**；期间倒置 → **P2** |
| 依据 | `LAW-CIVIL-502`、`POL-CON-6.12` |
| 误报提示 | 框架合同的签订先于具体订单签署属正常；追溯生效（如"自 2026-08-01 起对双方已发生的交易适用"）若**明示为追溯条款**则不判缺陷，但须提示其法律效果 |

### RULE-FMT-010　同一事项期限一致性

| 项 | 内容 |
| --- | --- |
| 适用对象 | 付款期限、交付期限、验收期限、质保期、违约金计算基数 |
| 判定逻辑 | 按"事项"聚类全文相关表述，检查取值是否唯一：① 交付期（固定日期 vs 相对期限）；② 验收期（3 日 vs 5 日）；③ 质保期（12 个月 vs 24 个月）；④ 违约金日费率与基数 |
| 命中动作 | 同一事项在不同条款取值不一致 → **P1**，输出全部冲突位置与取值 |
| 依据 | `POL-CON-6.12`（内部一致性） |
| 误报提示 | "初步验收/最终验收"分设不同期限属正常设计，聚类时应按**验收阶段**细分，避免把不同阶段误判为冲突 |

### RULE-FMT-011　币种与计量单位统一

| 项 | 内容 |
| --- | --- |
| 适用对象 | 全文币种符号、计量单位 |
| 判定逻辑 | 币种集合是否唯一；计量单位（台/套/组/米/件）与明细表是否一致；同一标的在不同条款的单位是否一致 |
| 命中动作 | 不统一 → **P3** |
| 依据 | `POL-CON-6.3` |
| 误报提示 | 允许"台（套）"等并列表述；外币折算说明不属不统一 |

### RULE-FMT-012　定义术语闭环

| 项 | 内容 |
| --- | --- |
| 适用对象 | "定义"条款与全文术语 |
| 判定逻辑 | ① 抽取定义条款中已定义术语集合 D；② 抽取全文加引号或首字母缩写的术语集合 U；③ 计算 U − D（使用但未定义）；④ 计算 D − U（定义但未使用） |
| 命中动作 | 关键术语未定义（验收合格、重大违约、损失、交付） → **P3**；定义但全文未使用 → **P3**（冗余） |
| 依据 | `POL-CON-5.5` |
| 误报提示 | 一般法律术语（合同、价款）不要求定义；仅对**在本合同中被赋予特定含义**的术语要求定义 |

### RULE-FMT-013　附件清单与实体一致性

| 项 | 内容 |
| --- | --- |
| 适用对象 | 附件条款与随附文件 |
| 判定逻辑 | ① 解析附件清单，得到声明集合 A；② 检查实际随附文件集合 B；③ A − B = 声明未提供；④ 检查是否约定 **附件与正文冲突时的优先顺序**；⑤ 检查正文引用的技术文件是否在 A 中 |
| 命中动作 | 声明附件缺失 → **P2**；未约定优先顺序 → **P2**；正文引用的文件未被列入清单 → **P2** |
| 依据 | `POL-CON-5.6` |
| 误报提示 | 电子签署场景下附件可能以独立文件上传，需检查签署包全部文件而非仅正文 |

### RULE-FMT-014　空白栏位检测

| 项 | 内容 |
| --- | --- |
| 适用对象 | 全文 |
| 判定逻辑 | 识别占位符与空值：`____`、`××××`、`【　】`、`[ ]`、`（待补充）`、"此处空白"、连续全角空格 ≥6 个；识别已标注但未填写的字段标签（如"银行账号："后无内容） |
| 命中动作 | 关键栏位空白（金额、期限、账号、主体信息） → **P2**；非关键栏位空白 → **P3** |
| 依据 | `POL-CON-8.1` |
| 误报提示 | 模板文件本身的占位符属设计意图，应提示"该文件疑似未完成填写的模板"而非逐项报缺陷 |

### RULE-FMT-015　合同份数与效力表述

| 项 | 内容 |
| --- | --- |
| 适用对象 | 结尾条款 |
| 判定逻辑 | 检查是否约定：① 合同份数；② 各方持有份数；③ **"具有同等法律效力"**表述；④ 正副本区分（如有） |
| 命中动作 | 缺同等效力表述 → **P3** |
| 依据 | `POL-CON-8.3` |
| 误报提示 | 电子签署且约定"以平台存证版本为准"的，不要求份数条款 |

### RULE-FMT-016　主体指向一致性

| 项 | 内容 |
| --- | --- |
| 适用对象 | 各条款中义务主体与权利主体的表述 |
| 判定逻辑 | **本规则需语义辅助，不能仅靠正则**：① 抽取每条中以"甲方/乙方/买方/卖方/供货方/采购方"开头的义务句；② 判断该义务在业务逻辑上应由哪一方承担（如"接收货物""支付价款"应由甲方，"交付货物""开具发票"应由乙方）；③ 比对实际表述的主体与应有主体 |
| 命中动作 | 主体错位 → **P3**，并给出"应为 X 方"的修改建议 |
| 依据 | `POL-CON-5.4` |
| 误报提示 | 反向义务（如"甲方不得迟延接收"）表述主体与目的相反属正常；**此规则误报率较高，应作为提示项而非阻断项** |

## 三、执行顺序与依赖

规则之间存在依赖关系，引擎须按以下顺序执行：

```
① RULE-FMT-007（建立条款编号索引）
      ↓
② RULE-FMT-008（交叉引用校验，依赖 ① 的索引）
      ↓
③ RULE-FMT-004、005、006（金额校验，互相独立，可并行）
      ↓
④ RULE-FMT-009、010（时间与期限校验，依赖抽取出的日期集合）
      ↓
⑤ RULE-FMT-001、002、003、014（要素完整性）
      ↓
⑥ RULE-FMT-011、012、013、015（统一性与清单）
      ↓
⑦ RULE-FMT-016（语义校验，最后执行，需完整上下文）
```

**前置失败处理**：若 ① 因条款结构严重混乱而无法建立索引，② 应跳过并在报告中标注"因条款编号不可解析，交叉引用校验未执行"——**不得静默跳过**。
