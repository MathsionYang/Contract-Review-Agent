# 规则覆盖率与埋点映射

## 一、这份文件解决什么问题

有了带缺陷的测试样本，还需要回答一个问题：**规则库能不能覆盖样本里的每一个埋点？**

如果某个埋点在规则库里找不到对应规则，那么无论审批助手多聪明，它都无法给出一致、可复核的判定——只能凭模型的临场发挥。本文件就是做这个比对。

**比对结果**：40 个埋点中，**40 个已覆盖**（100%）。其中 33 个由最初的 `RULE-FMT` + `RULE-BIZ` 覆盖，7 个在比对时发现没有对应规则，为此新增了 `RULE-PRC` 域（见第五节）。

## 四、埋点的"识别难度"与规则的关系

同一等级的埋点，对工具的要求并不相同。下表把埋点按**所需能力**归类，这对评测最有价值：

| 能力层级 | 埋点 | 需要工具具备什么 |
| --- | --- | --- |
| **L1 关键词/单条判断** | D-01、D-03、D-19 | 识别"100% 预付""赔偿不超过 X%""知识产权归乙方"这类高风险表述 |
| **L2 数值归一与阈值比对** | D-02、D-13、D-16、D-39 | 把"万分之五""0.5%""日千分之五"归一化后与阈值比较；换算年化 |
| **L3 跨条款比对** | D-06、D-07、D-10、D-12、D-15、D-33 | 同一事项在不同条款的取值是否冲突；含税定性是否唯一 |
| **L4 结构化推理** | D-05、D-24、D-26、D-27、D-35、D-36、D-37、D-40 | 大小写金额解析；信用代码位数；引用目标存在性；日期时序；主体指向 |
| **L5 需上下文参数** | D-08、D-09、D-11、D-13、D-19 | 必须知道标的物属性（设备关键性、是否送货上门、是否定制开发）才能判定，否则必然大量误报 |

**L5 是评测的分水岭**：一个工具如果能问出"这批设备用于产线还是仓库"，它的判定质量会立刻与其他工具拉开差距。

## 五、缺口分析与规则补全

初次比对时，下列 7 个埋点**在规则库中找不到对应规则**：

| 埋点 | 缺陷 | 为什么原有规则覆盖不到 |
| --- | --- | --- |
| D-13 | 售后 SLA 过宽且无违约后果 | 属于"条款有但不完整"，不是阈值越界 |
| D-14 | 质保后维修定价权单方归属 | 同上 |
| D-28 | 通知送达不完整 | 同上 |
| D-29 | 变更程序缺失 | 同上 |
| D-30 | 包装与装卸责任缺失 | 同上 |
| D-32 | 解除后果未约定 | 同上 |
| D-34 | 费用转嫁无上限 | 属于"多项小额条款形成组合敞口"，单条都够不上阈值 |

**共性**：这些缺陷的特征是**条款"看起来有"，但缺了关键要件**，导致履行中无法主张权利。它们既不属于纯文本形式问题（`RULE-FMT`），也不属于阈值越界（`RULE-BIZ`）——任何基于关键词扫描的工具都会漏掉它们。

为此新增 **`RULE-PRC`（流程与文本完整性）** 域，含 6 条规则：

| 规则 | 名称 | 覆盖埋点 |
| --- | --- | --- |
| `RULE-PRC-001` | 通知与送达条款完整性 | D-28 |
| `RULE-PRC-002` | 合同变更与补充协议规范 | D-29 |
| `RULE-PRC-003` | 解除后的结算与处理约定 | D-32 |
| `RULE-PRC-004` | 包装、运输与装卸责任 | D-30 |
| `RULE-PRC-005` | 费用转嫁的边界与上限 | D-34 |
| `RULE-PRC-006` | 售后响应时限与违约后果 | D-13、D-14 |

**这条经验值得记下来**：设计规则库时，最容易忽略的既不是形式校验，也不是阈值设定，而是**"条款完备性"**。而恰恰是这一类缺陷，在真实合同争议中造成的损失最直接——因为缺少的往往正是争议发生时唯一的救济路径。

## 六、怎么用这套东西评测审批助手

### 6.1 三步法

| 步骤 | 操作 | 观察什么 |
| --- | --- | --- |
| ① 上传样本 | 把 `设备采购合同-HLXQ-CG-2026-0917.docx` 交给被测工具 | 是否正常解析、是否识别为采购合同 |
| ② 对照答案卡 | 用 `缺陷埋点清单与预期定级.md` 逐项核对 | 检出率、分级准确率、是否有编造的缺陷 |
| ③ 检查依据质量 | 看它的每条意见是否给出可追溯依据 | **关键**：依据是否真实存在、是否指向正确条款 |

第 ③ 步是这套知识底座真正的用途。一个工具说得头头是道但依据含糊，和一个工具能明确说出"依据 `RULE-BIZ-004`，该条款日费率 0.5%，折年化 182.5%，超过阈值 0.05%"——后者才是可被审计、可被信任的。

### 6.2 分级通过标准

| 等级 | 标准 | 说明 |
| --- | --- | --- |
| 不合格 | P0 检出率 < 100% | 致命缺陷漏检直接否决 |
| 合格 | P0 全检出、总检出率 ≥ 70%、能识别 ≥ 2 项 L3 跨条款冲突 | — |
| 良好 | 上述 + L4 结构化推理类埋点检出 ≥ 5 项（D-05、D-24、D-26、D-27、D-35~D-37、D-40 中） | L4 靠的是工程实现，不是模型聪明 |
| 优秀 | 上述 + 主动追问上下文（L5），并明确区分"命中阈值"与"条款无效" | 不把企业红线说成法律禁止 |

### 6.3 误报判定

答案卡第六节列出的 14 条中性条款是**误报陷阱**。其中三条最容易误判，需要特别说明：

| 埋点/条款 | 常见误报 | 正确判定 |
| --- | --- | --- |
| 8.2"视为验收合格" | 一律判为"霸王条款" | 该条款有 `LAW-CIVIL-621` 作为法律基础，**本身不违法**；问题在于搭配的 3 日验收期不合理 |
| 售后 12 个月 | 判为"质保期过短" | 12 个月对仓储设备属常规；真正的问题是**同一份合同里另写 24 个月**（内部冲突） |
| 11.1–11.3 IP 条款 | 一律判"IP 归乙方=高风险" | 标准产品的基础软件授权归厂商属行业惯例，**应判 P2 并提示约定永久许可**，而非 P0 |

这三条正好对应 `RULE-BIZ-011`、`RULE-BIZ-012`、`RULE-BIZ-015` 中标注的"误报提示"——规则设计时把这些陷阱写进去，就是为了防止工具"见关键词就报警"。
