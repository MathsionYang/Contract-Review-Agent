# 确定性规则集 · 流程与文本完整性

> **本域存在的原因**：在把测试样本的全部埋点与 `RULE-FMT`、`RULE-BIZ` 做映射时，发现 6 类缺陷**没有对应规则**——它们既不属于纯形式校验，也不属于阈值判定，而是**条款内容的完备性**问题。
> 这类缺陷的共同特征是：条款本身"看起来有"，但缺了关键要件，导致履行中无法主张权利。关键词扫描工具最容易漏掉它们。

## 二、逐条判定逻辑

### RULE-PRC-001　通知与送达条款完整性

| 项 | 内容 |
| --- | --- |
| 适用对象 | 通知与送达条款 |
| 判定逻辑 | 检查下列要素是否齐备：① **双方**的送达地址（不是只有一方）；② **双方**的电子邮箱或其他电子送达方式；③ 送达生效规则（到达生效 or 发出生效）；④ 地址/联系方式**变更时的通知义务**及未通知的后果；⑤ 送达地址是否与首部主体信息一致 |
| 命中动作 | 仅列一方送达信息 → **P2**（无法向我方有效送达，或我方送达无法举证）；无变更通知义务 → **P2**；约定"发出即视为送达"且无任何到达保障机制 → **P2**；地址与首部不一致 → **P2** |
| 依据 | `POL-CON-6.12`；`LAW-CIVIL-509`（诚信原则下的通知义务）；`LAW-ESIGN-10`（数据电文到达时间的确定） |
| 误报提示 | 约定"以专人送达为主、电子送达为辅"的双轨体系属规范做法；已约定送达地址确认书作为附件的，视为齐备 |
| 判定要点 | "发出即视为送达"本身**不违法**——它是对送达规则的约定。风险在于：① 我方的送达地址缺失时，对方可以单方向我方"发出"却无需我方实际知悉；② 无变更通知义务时，对方迁址后仍可主张向我方旧地址送达有效。**判定要落在"是否对等"，而不是落在"发出即送达"这个措辞上** |

### RULE-PRC-002　合同变更与补充协议规范

| 项 | 内容 |
| --- | --- |
| 适用对象 | 合同变更条款 |
| 判定逻辑 | 检查是否约定：① 变更须采用**书面形式**；② 有效签署人及其**权限**；③ 补充协议与原合同**不一致时的效力顺序**；④ 涉及金额、期限、责任变更时的重新审批要求（引用 `POL-CON-9.3`） |
| 命中动作 | 仅约定"协商一致可变更"而无书面要求 → **P2**；无效力顺序约定 → **P2**；无签署权限约定 → **P2** |
| 依据 | `POL-CON-9.3`（变更须书面、明确签署权限与效力顺序）；`LAW-CIVIL-509`（诚信原则下的通知、协助义务） |
| 误报提示 | 合同已在"通知"条款中约定"书面形式包括电子邮件、传真、即时通讯记录"的，可视为满足书面要求，不判缺陷 |
| 判定要点 | 这条风险的现实表现是：业务人员用微信口头同意降价 5%，对方事后主张已变更。**"协商一致可变更"这七个字在实务中等于没有约定变更程序** |

### RULE-PRC-003　解除后的结算与处理约定

| 项 | 内容 |
| --- | --- |
| 适用对象 | 合同解除条款及结算条款 |
| 判定逻辑 | 检查是否约定解除后：① 已交付设备/软件的处理（返还、折价、继续使用）；② 软件许可是否随合同解除而终止；③ **已付款项的处理**（退还比例与期限）；④ 已完成工作量或已交付部分的结算方式；⑤ 双方的其他义务（数据返还与删除、保密义务存续） |
| 命中动作 | 无任何解除后结算约定 → **P2**；约定"已收货款不予退还"而无对价说明 → **P1**（不当得利风险）；约定解除后软件许可立即终止而价款不退还 → **P1** |
| 依据 | `LAW-CIVIL-566`（解除后已履行部分可请求恢复原状或采取补救措施，并有权请求赔偿损失）；`POL-CON-9.5` |
| 误报提示 | 分期履行合同中逐期结算的，解除后按已履行期结算属正常，不判缺陷 |
| 判定要点 | 解除条款往往只写"谁有权解除"，却不写"解除后怎么算账"，导致解除权形同虚设——**解除后无法收回已付款，等于没有解除权** |

### RULE-PRC-004　包装、运输与装卸责任

| 项 | 内容 |
| --- | --- |
| 适用对象 | 包装、运输、装卸相关条款 |
| 判定逻辑 | 检查是否约定：① **包装标准**（尤其木质包装的 ISPM 15 检疫要求、危险品包装要求）；② **装车与卸车责任划分**（大型设备的吊装责任、机具与人员由谁提供）；③ 超限运输的许可办理责任与费用；④ 包装物的回收义务与费用 |
| 命中动作 | 无装卸责任划分 → **P2**；无包装标准 → **P2**；涉及木质包装或危险品而无检疫/合规约定 → **P1** |
| 依据 | `LAW-CIVIL-619`（按约定包装方式交付） |
| 误报提示 | 小型标准品（免安装、普通纸箱包装）可不单独约定装卸责任，不判缺陷 |
| 判定要点 | 大型设备采购中，**卸货吊装是事故高发环节**。责任未划分时，一旦货物或人员受损，双方都会主张对方负责。此类条款缺失应结合标的物属性判断——这也是本规则需要"标的物类型"作为输入参数的原因 |

### RULE-PRC-005　费用转嫁的边界与上限

| 项 | 内容 |
| --- | --- |
| 适用对象 | 仓储费、水电费、差旅费、机具费、停工损失等费用承担条款 |
| 判定逻辑 | ① 提取全部"由甲方承担"的费用项；② 检查每一项是否约定了**计费标准、计费方式、上限**；③ 检查费用产生的**触发条件是否由该方可控**（如"因甲方原因导致" 属可控；"因客观情况" 属不可控）；④ 检查是否约定费用需提供凭证 |
| 命中动作 | 费用事项归我方但无标准与上限 → **P2**；触发条件不可控且无上限 → **P2**；约定"一切后果由甲方承担"等开放式表述 → **P2**；多项此类条款并存 → 升级为 **P1**（形成费用敞口） |
| 依据 | `POL-CON-6.6`、`POL-CON-9.3`；《民法典》第 6 条公平原则 |
| 误报提示 | 我方原因导致的相应费用由我方承担属合理，不判缺陷；关键在于**是否有上限与凭证要求** |
| 判定要点 | 单看一条"仓储费由甲方承担"不是问题；合同里同时出现仓储费、水电费、网络费、差旅费、工期顺延损失等五处开放式费用条款时，才构成**组合型敞口**。本规则必须支持**累计计数后再升级等级** |

### RULE-PRC-006　售后响应时限与违约后果

| 项 | 内容 |
| --- | --- |
| 适用对象 | 售后服务条款 |
| 判定逻辑 | ① 提取响应时限与到场时限；② 与阈值比对（响应 ≤ 8 小时；到场 ≤ 3 个工作日）；③ 检查是否约定**超时的违约责任**；④ 检查是否约定备件供应年限（建议 ≥ 8 年）；⑤ 检查返厂维修期间是否提供替代设备；⑥ 检查返厂运输费用由谁承担 |
| 命中动作 | 响应 > 8 小时或到场 > 3 个工作日 → **P1**（对产线关键设备）／P2（对非关键设备）；超时无违约后果 → **P2**；无备件供应年限 → **P2**；返厂运输费由我方承担 → **P2** |
| 依据 | `POL-CON-6.7` |
| 误报提示 | **这是误报与漏报都高发的规则**。办公设备 72 小时响应属正常，不应报警；而产线核心设备的 72 小时响应足以造成数十万元停产损失。**必须引入"设备关键性"作为输入参数**，否则本规则无意义 |
| 判定要点 | 阈值不能只有一套。本规则应实现为**按设备关键性分档的阈值表**：

| 设备类别 | 响应时限 | 到场时限 | 缺违约后果的处理 |
| --- | --- | --- | --- |
| 产线核心设备 | ≤ 4 小时 | ≤ 24 小时 | 命中 P1 |
| 物流与仓储设备 | ≤ 8 小时 | ≤ 3 个工作日 | 命中 P2 |
| 办公与辅助设备 | ≤ 24 小时 | ≤ 5 个工作日 | 提示，不计等级 |

## 三、与既有规则域的关系

| 域 | 覆盖范围 | 判定特征 |
| --- | --- | --- |
| `RULE-FMT` | 文本层面的形式正确性 | 完全确定性，不依赖业务知识 |
| `RULE-BIZ` | 商业条款的风险阈值 | 确定性阈值 + 少量范围判断 |
| `RULE-PRC`（本域） | 条款内容的完备性 | **需要"标的物属性"作为上下文参数** |

三域的调用顺序建议为 `FMT → PRC → BIZ`：

1. `FMT` 先把文本规范化（编号、金额、日期），为后续规则提供干净输入；
2. `PRC` 判断条款内容是否完备（需要标的物类型、设备关键性等上下文）；
3. `BIZ` 在内容完备的前提下判断阈值是否越界。

**顺序不可颠倒**：若条款本身缺失（`PRC` 未通过），直接跑 `BIZ` 会产生大量"找不到目标条款"的空转；反之若 `FMT` 未先运行，条款编号与日期不可靠，`PRC` 与 `BIZ` 的定位会出错。

## 四、结果输出格式

```json
{
  "rule_id": "RULE-PRC-006",
  "severity": "P1",
  "hit": true,
  "location": "第九条（售后服务）第 9.2 款",
  "context": { "device_criticality": "物流与仓储设备", "threshold_profile": "物流" },
  "actual": "响应 72 小时，到场 15 个工作日，无超时违约约定",
  "basis": ["POL-CON-6.7"],
  "suggestion": "响应时限压缩至 8 小时、到场压缩至 3 个工作日；增设超时违约金（每超 1 日按合同总价 0.05%）与累计超时解除权；约定备件供应年限不少于 8 年",
  "confidence": 1.0
}
```

`context` 字段在本域中是**必需项**——缺少标的物属性时，规则应输出"无法判定，请补充设备类别"而非给出猜测结论。
