# 合同审查内容体系与通用审查清单

> 版本：v1.0
> 编写日期：2026-09-15
> 适用范围：中国大陆企业内部合同实务（采购、销售、服务、租赁、软件开发等民商事合同）
> 文档定位：合同审查领域知识底座——既是法务/业务人员的审查清单，也是「合同审查 Agent」的检查项来源
> 关联文档：`合同审查Agent需求说明.md`（v0.4）

## 0. 文档说明

### 0.1 这份文档解决什么问题

「合同审查」四个字在实务中含混，不同人对它的理解差异极大：有人理解为挑错别字，有人理解为改条款，有人理解为审合法性。这份文档要把它拆成**可执行、可勾选、可编码**的检查项体系。

### 0.2 使用方式

| 角色 | 用法 |
|---|---|
| 法务 / 业务审查人 | 用第 4 章通用清单逐项过，用第 5 章看专项要点，用第 2/3 章回看原理 |
| Agent / 规则库设计者 | 第 4 章编号条目 = 候选检查项，第 6.1 节给出「确定性规则 / 语义判断」的划分依据 |
| 新人培训 | 按第 2 → 3 → 4 章顺序读，第 7 章作为「踩坑速查」 |

### 0.3 法律依据口径声明

- 本文引用法条以《民法典》（2021-01-01 施行）、《民事诉讼法》（2023 修正，2024-01-01 施行）、《招标投标法》、《个人信息保护法》等现行文本为基础，**条号已尽量核对**（第 35 条协议管辖、第 686 条保证方式等已二次查证）。
- 凡标注 **〔待核〕** 的条号或口径，表示未完成最终文本核对或存在版本变动风险，**不得直接作为对外法律结论引用**，须回权威数据库（北大法宝等）核验。
- 本文是**审查方法论与检查清单**，不构成法律意见。地方司法口径、行业监管细则与个案事实会显著影响结论。

## 1. 先定性：合同审查到底在审什么

### 1.1 三层目标（从低到高）

| 层次 | 目标 | 审不出来会怎样 | 审查手段 |
|---|---|---|---|
| **L0 形式合法** | 签得成、认得出、拿得出 | 合同不成立、主体错误、无授权，争议时无法举证 | 文件核验、形式检查 |
| **L1 效力与合规** | 合同有效、不被认定无效或部分无效 | 条款白签、无效后按法定规则处理，商务安排落空 | 法律检索、强制性规定比对 |
| **L2 可执行 / 可救济** | 对方违约时，我方能低成本拿到赔偿或实现权利 | 赢了道理输了钱：无管辖、无证据、无担保、赔偿受限 | 条款设计分析、证据链推演 |
| **L3 商业目的达成** | 交易结构、价格机制、退出路径真的支撑业务目标 | 合同有效且可诉，但生意本身做不成或做亏 | 商务与业务联合评审 |

**实务中最常见的问题不是 L1（合法性），而是 L2**——绝大多数合同纠纷的败因不是条款违法，而是「没有约定清楚 + 没有约定怎么救济」。

### 1.2 一句核心判据

> 审查的本质是**反事实推演**：假设对方明天违约、假设项目中途做不下去、假设出了事故、假设三年后要打官司——逐条问「按现在这份合同，我方能拿到什么？」

凡是回答不了这个问题的条款，就是审查要动的地方。

### 1.3 与相邻概念的区别

| 概念 | 关注点 | 与合同审查的关系 |
|---|---|---|
| 合同起草 | 从零设计交易结构 | 审查的前置或同源工作；起草质量决定审查工作量 |
| 合同审查 | 对已成稿合同做风险识别与修改建议 | 本文主题 |
| 法律意见书 | 对特定法律问题出具专业结论 | 审查意见可为意见书的事实基础，但不等同 |
| 财务 / 税务审核 | 价格、发票、资金、税负合规 | 与审查交叉于「价款与支付」块，须联合把关 |
| 合规审查 | 是否触碰监管红线（反垄断、反腐、数据） | 与第 5 章 L5 高度重叠 |
| 商务审批 | 是否符合商业利益与预算 | 审查只提供风险输入，不替代商务判断 |

## 2. 审查内容总框架（六层）

把合同文本拆成六层，逐层审。**顺序不可颠倒**：主体不成立，条款写得再漂亮也没用。

| 层 | 名称 | 审什么（一句话） | 失守的典型后果 | 谁主责 |
|---|---|---|---|---|
| **L1** | 主体与效力基础 | 跟谁签、他有没有资格签、签了算不算数 | 主体错误、无权代理、效力待定、无法执行 | 法务 |
| **L2** | 标的与商务条款 | 买什么、多少钱、怎么付、怎么交、怎么验 | 履行标准争议、付款被拒、验收扯皮 | 业务 + 财务 |
| **L3** | 权利义务配置 | 谁干什么、谁先干、谁能改、成果归谁 | 义务失衡、单方变更、知识产权流失 | 业务 + 法务 |
| **L4** | 风险分配与救济 | 出事谁担责、赔多少、怎么退出、去哪打 | 赔偿受限、无担保、无管辖、赢了拿不到钱 | 法务 |
| **L5** | 合规与程序 | 有没有踩红线、内部外部程序走没走完 | 合同无效、行政处罚、内控失效 | 法务 + 合规 |
| **L6** | 文本质量与形式 | 条款齐不齐、前后一致不、签得对不对 | 条款冲突、引用失效、举证困难 | 审查人 |

### 2.1 与经典「形式审查 / 实质审查」二分的映射

| 经典分类 | 对应本文层级 | 内容 |
|---|---|---|
| 形式审查 | L1（资质文件部分）+ L6 | 主体资料是否齐全、签署是否规范、附件是否完整、文本是否一致 |
| 实质审查 | L2 + L3 + L4 + L5 + L1（授权/决议部分） | 条款内容是否合法、公平、可执行 |

形式审查是**门槛**：形式不全，实质审查没有对象。

## 3. 逐层详解

### 3.1 L1 主体与效力基础

#### 3.1.1 主体身份核验

| 检查点 | 具体要求 | 常见问题 |
|---|---|---|
| 名称一致性 | 合同抬头、签署页、正文提及、发票抬头、收款账户名**四处必须完全一致** | 简称/全称混用；「有限公司」与「有限责任公司」不一致 |
| 统一社会信用代码 | 必填，与营业执照一致 | 手抄错位；旧版注册号冒充 |
| 主体资格 | 存续状态、是否被吊销/注销/列入经营异常、是否进入破产程序 | 已注销企业签约；吊销后仍以原名义签约 |
| 经营范围 | 是否超出登记经营范围（一般不影响效力，但涉许可经营的除外） | 无资质从事特许业务 |
| 特殊资质 | 建筑资质等级、医疗器械经营许可、食品经营许可、人力资源服务许可、ISP/ICP 等 | 借用资质（挂靠）——合同可能无效且责任自担 |
| 履约能力 | 注册资本、实缴、涉诉、被执行、失信名单 | 空壳公司承接大额合同 |

#### 3.1.2 签署权限核验

| 检查点 | 要点 |
|---|---|
| 法定代表人签署 | 核对姓名与登记一致；法定代表人变更后以现任为准 |
| 授权代表签署 | 必须有**授权委托书原件**，且授权范围覆盖本合同事项、期限覆盖签署日 |
| 经办人越权 | 构成表见代理的风险与「善意相对人」认定 |
| 印章类型 | 公章、合同专用章均可；财务章、部门章、项目部章**通常不足以代表法人**（最高人民法院相关裁判口径偏严，具体个案判断） |
| 印章真实性 | 电子章/扫描章的伪造风险；建议对重要合同采取「面签 + 骑缝章 + 名片核验」 |
| 内部决议 | 担保、对外投资、重大资产处置、关联交易是否需股东会/董事会决议（《公司法》相关担保决议要求〔待核最新文本〕） |
| 国资/上市程序 | 国资需评估、审批、进场交易；上市公司需披露与审批 |

#### 3.1.3 三类主体错位的陷阱

1. **签约主体 ≠ 履约主体**：合同与 A 签，实际由 B 干活 → 出事找不到责任人。
2. **签约主体 ≠ 付款主体**：与 A 签、要求付给 B → 付款义务履行的抗辩风险、虚开风险。
3. **签约主体 ≠ 责任主体**：与子公司签、指望母公司兜底 → 母公司无义务，须另行取得保证或安慰函。

> **审查动作**：对「三方错位」情形，必须要求**在同一合同中明确各自角色**，或另行签署补充协议/担保文件。

### 3.2 L2 标的与商务条款

#### 3.2.1 标的描述

| 检查点 | 要求 | 反例 |
|---|---|---|
| 名称与规格 | 名称、品牌、型号、规格、材质、产地、技术参数 | 「一批办公用品」「若干软件」 |
| 数量与单位 | 数量、计量单位、溢短装与损耗率 | 单位缺失（吨/件/台） |
| 质量标准 | 国标/行标/企标/双方确认的样品或技术文件，须**指明具体编号与版本** | 「符合国家标准」不写是哪一项 |
| 服务类标的 | 用 SOW（工作说明书）描述范围、交付物、里程碑 | 只写「提供咨询服务」 |
| 配套文件 | 技术协议、图纸、报价单、需求文档作为附件并明确效力顺序 | 附件未签、未编版本号 |

#### 3.2.2 价格、税率与发票

| 检查点 | 要点 | 常见坑 |
|---|---|---|
| 含税/不含税 | 必须写明，且注明税率与税目 | 「合同价 100 万」——含不含税吵半年 |
| 税率变化 | 约定税率调整机制（政策性调整时价款如何变动） | 税率下调，供方吃掉差额 |
| 发票类型 | 增值税专用发票 / 普通发票，开票时限、开票信息 | 收到普票不能抵扣 |
| 付款与开票顺序 | 先票后款 or 先款后票，是否构成付款前置条件 | 供方不开票，买方拒付是否构成违约 |
| 发票瑕疵救济 | 约定发票不合规时的补开、换开及赔偿责任 | 只写「应开具发票」，无违约后果 |
| 价款构成 | 单价、总价、税费、运费、保险、安装调试、备件是否已包含 | 后续追加费用 |

#### 3.2.3 支付条款（实务争议第一名）

| 检查点 | 要点 |
|---|---|
| 比例结构 | 预付款/到货款/验收款/质保金的百分比，合计必须 = 100% |
| 账期与起算点 | 「收到发票后 30 日」还是「验收合格后 30 日」，起算点必须唯一可确定 |
| 付款前置单据 | 发票、验收单、进度确认单、保函——清单化列明 |
| 付款条件可达成性 | 条件是否由对方单方控制（如「买方满意后付款」→ 无效或条件成就拟制） |
| 账户信息 | 户名、开户行、账号，且户名须与主体一致；变更账户须书面确认（防诈骗） |
| 逾期付款 | 利息或违约金的计算方式与标准 |
| 资金合规 | 是否涉及商业贿赂、返利、账外支付 |

#### 3.2.4 交付、验收与质保

| 检查点 | 要点 |
|---|---|
| 交付时间 | 具体日期或相对期限，起算点明确（合同生效日？预付款到账日？） |
| 交付地点与方式 | 送达即视为交付 / 签收单 / 物流单据 |
| 风险转移 | 交付主义 vs 特定地点（如 FOB/EXW/DAP/DDP 术语）——**风险转移点 ≠ 所有权转移点，须分别约定** |
| 所有权保留 | 是否约定价款未付清前所有权保留，及登记对抗问题 |
| 验收标准与期限 | 标准（附件/技术文件）、期限、主体（谁验收）、方式（抽检/全检） |
| 视为验收 | 约定「逾期未提出异议视为验收合格」，绑定明确期限（如 10 个工作日） |
| 验收不合格救济 | 修理/重做/退货/减价/解除，以及**次数上限**（防止无限整改拖死项目） |
| 质保期与保修 | 起算点（验收合格日/交付日）、期限、范围、响应时限（SLA）、费用承担 |
| 备件与文档 | 备件供应承诺、操作手册、源代码/设计文档交付 |

#### 3.2.5 一致性交叉检查（可用规则引擎自动做）

| 检查项 | 方法 |
|---|---|
| 金额大小写一致 | 正则比对中文大写与小写 |
| 总价 = 单价 × 数量 | 数学校验 |
| 日期逻辑 | 签订日 ≤ 生效日 ≤ 交付日 ≤ 验收日 ≤ 质保到期日；付款节点不得早于前置事件 |
| 比例合计 | 各期付款比例之和 = 100%，质保金比例与退还条件对应 |
| 期限一致 | 正文期限 vs 附件/SOW 期限 |
| 主体一致 | 全文主体名称、账户户名一致 |
| 交叉引用有效 | 「见第 X 条」的 X 条是否存在，引用内容是否匹配 |
| 附件齐全 | 附件清单列出的每一份附件是否实际存在并已签 |

### 3.3 L3 权利义务配置

| 检查点 | 典型失衡表现 | 修改方向 |
|---|---|---|
| 履行顺序 | 未约定谁先履行 → 同时履行抗辩 vs 先后履行抗辩 | 明确先后顺序，绑定付款/交付节点 |
| 单方变更权 | 「甲方有权单方调整需求/规格/数量」 | 设定变更流程、书面确认、计价规则、上限 |
| 配合义务 | 「乙方应无条件配合甲方一切要求」 | 限定范围、时限、成本承担方 |
| 排他 / 独家 | 排他期、排他范围不清，无对价 | 明确期限、地域、品类、最低采购量对价、违反后果 |
| 最惠待遇 | 无对价、无验证机制 | 加对价（承诺量）与验证与救济 |
| 知识产权归属 | 只写「成果归甲方」未区分背景 IP / 前景 IP / 通用工具 | 分层约定：背景 IP 保留、前景 IP 归属、通用组件许可回授 |
| 职务成果与开源 | 未处理员工成果、第三方开源组件 | 加「不侵权声明 + 开源清单披露 + 侵权赔偿」 |
| 商标与品牌 | 授权范围、期限、品质控制、终止回收 | 明确许可类型与终止后清理 |
| 保密 | 未约定保密期限、例外、返还销毁 | 见 5.6 NDA 专项 |
| 数据合规 | 未约定个人信息角色、处理目的、期限、跨境 | 按《个人信息保护法》委托处理/共同处理条款落地 |
| 人员与服务水准 | 无 SLA、无 KPI、无替换机制 | 加 SLA 指标（可用率/响应/恢复）+ 扣款 + 退出 |

### 3.4 L4 风险分配与救济

#### 3.4.1 违约责任

| 检查点 | 要点 | 风险提示 |
|---|---|---|
| 违约金基数 | 按日万分之几 / 按合同总额百分比 / 按实际损失 | 基数未写「合同总价」而写「未履行部分」，计算争议 |
| 违约金上限 | 通常 5%~20% 封顶 | 无上限 → 对方可能主张过高；上限过低 → 约束力不足 |
| 违约金与损失赔偿关系 | 是否「违约金不足以弥补损失时可另行索赔」 | 未写 → 可能被解释为损失赔偿的唯一救济 |
| 违约金过高调减 | 《民法典》第 585 条：过分高于损失的可请求调减；实务常引「超过损失 30%」为参考线（《民法典合同编通则解释》相关条款，条号〔待核〕） | 高额违约金≠可执行 |
| 责任上限 | 是否约定赔偿上限（合同总价/已付款金额）、是否排除间接损失 | 上限过低会一起封住我方的索赔 |
| 上限例外 | 保密、知识产权侵权、故意或重大过失、人身损害**应排除在上限之外** | 未排除 → 对方泄密也只赔 10% |

#### 3.4.2 担保与增信

| 检查点 | 要点 |
|---|---|
| 保证方式 | **必须明确写「连带责任保证」**——《民法典》第 686 条：没有约定或约定不明的，按**一般保证**承担（这与已被废止的《担保法》推定连带责任的规则相反），保证人享有先诉抗辩权 |
| 保证期间 | 约定明确期间；未约定或约定不明的，为主债务履行期限届满之日起 **6 个月**（《民法典》第 692 条） |
| 保证人资格 | 是否为国家机关、公益性事业单位、企业分支机构（未经授权）等不得作保证人的主体 |
| 抵质押 | 标的权属清晰、是否已抵押、是否需办理登记（不动产抵押、股权质押须登记才设立） |
| 保证金 / 保函 | 形式（银行保函/履约保函）、金额、退还条件与时限、见索即付与否 |
| 安慰函 / 支持函 | 通常不构成保证，仅为道义支持——**不能当作担保用** |
| 其他增信 | 所有权保留、共同债务人、差额补足、回购承诺（注意是否构成保证） |

#### 3.4.3 免责、不可抗力与情势变更

| 检查点 | 要点 |
|---|---|
| 不可抗力定义 | 列明情形（自然灾害、战争、疫情、政府行为），并约定**通知义务与举证期限** |
| 通知与举证 | 应在合理期限内（如 15 日）书面通知并提供证明，逾期不得免责 |
| 持续影响 | 超过一定期限（如 60 日）任一方有权解除并按已履行部分结算 |
| 情势变更 | 《民法典》第 533 条：基础条件重大变化且不属于商业风险的，可请求重新协商；协商不成请求法院/仲裁机构变更或解除 |
| 免责条款效力红线 | 《民法典》第 506 条：造成对方**人身损害**的免责条款、因**故意或重大过失**造成对方**财产损失**的免责条款**无效** |
| 保险 | 谁投保、险种、保额、被保险人/受益人、免赔额、未投保的后果 |

#### 3.4.4 解除与退出

| 检查点 | 要点 |
|---|---|
| 约定解除事由 | 具体化（逾期交付超 X 日、验收连续两次不合格、资质被吊销……），避免「严重违约」这类不可判定的表述 |
| 整改宽限期 | 解除前先通知 + 给 cure period（如 30 日），程序上更稳 |
| 根本违约界定 | 明确哪些情形直接构成根本违约 |
| 解除后果 | 已完成部分如何结算、已付款项是否退还、资料/设备/账号移交、在制品与备件处理 |
| 存续条款 | 保密、知识产权、争议解决、责任限制条款在解除后继续有效 |
| 单方任意解除 | 是否给对方任意解除权（会否导致我方前期投入打水漂） |

#### 3.4.5 争议解决（最容易被忽视、后果最严重）

| 检查点 | 要点 | 常见致命错误 |
|---|---|---|
| 诉讼 vs 仲裁 | 二选一，**不能同时约定**（或诉或裁条款可能被认定无效） | 「可向法院起诉，也可申请仲裁」 |
| 仲裁机构 | 必须写**唯一、准确、真实存在的机构全称** | 写「仲裁委员会」「当地仲裁机构」→ 仲裁协议可能无效，只能诉讼 |
| 管辖法院 | 协议管辖只能选与争议有实际联系的地点（被告住所地、合同履行地、合同签订地、原告住所地、标的物所在地）——《民事诉讼法》（2023 修正）第 35 条 | 选「甲方所在地」但甲方所在地与争议无实际联系 |
| 级别与专属管辖 | 不得违反级别管辖与专属管辖（不动产、港口作业、继承为专属管辖，民诉法第 34 条） | 约定不动产纠纷由外地法院管辖 → 无效 |
| 适用法律 | 涉外合同必写；国内合同通常不必 | 涉外合同漏写 |
| 送达地址条款 | 明确送达地址、收件人、电话、邮箱，并约定「按此送达即视为有效送达，地址变更须书面通知」 | **漏写送达条款 = 对方失联时无法推进程序** |
| 律师费与保全费 | 约定由违约方承担 | 未约定 → 通常只能自担 |
| 语言与文本 | 多语言版本冲突时的优先顺序 | 中英文本冲突无优先约定 |
| 时效 | 《民法典》第 188 条：诉讼时效 3 年 | 遗忘时效导致胜诉权丧失 |

### 3.5 L5 合规与程序

#### 3.5.1 效力红线（《民法典》第 153、154、156 条）

| 类型 | 举例 | 后果 |
|---|---|---|
| 违反法律、行政法规的强制性规定 | 无证经营特许业务、违法转包分包、变相高利贷、未招标直接发包必须招标项目 | 合同无效（该强制性规定不导致无效的除外） |
| 违背公序良俗 | 赌债、代孕、规避限购 | 无效 |
| 恶意串通损害他人合法权益 | 双方合谋损害第三方或债权人利益 | 无效 |
| 部分无效 | 仅某一条款无效，其余仍有效（第 156 条）；无效后返还财产、折价补偿、赔偿损失（第 157 条） | 条款级风险 |

#### 3.5.2 行业与专项合规

| 领域 | 关注点 |
|---|---|
| 招投标 | 必须招标项目的范围；中标通知书发出后 30 日内订立书面合同；**不得再行订立背离合同实质性内容的其他协议**（《招标投标法》第 46 条）；围标串标 |
| 建设工程 | 资质等级匹配、禁止转包与违法分包、必须招标、政府投资项目审批、价款优先受偿（《民法典》第 807 条） |
| 反商业贿赂 | 廉洁条款、佣金与居间费合理性、禁止账外支付、员工收受回扣的责任 |
| 反垄断与反不正当竞争 | 纵向价格限制（固定转售价格、限定最低转售价）、排他交易、地域限制的合规边界 |
| 数据与个人信息 | 处理个人信息须有合法性基础（《个人信息保护法》第 13 条）；委托处理须签协议并约定处理目的、期限、方式、安全措施（第 21 条）；数据出境需走安全评估/认证/标准合同等路径（第 38 条及配套规定） |
| 出口管制与制裁 | 是否涉及受管制物项、技术出口、受限主体名单 |
| 外汇与跨境 | 跨境支付路径、外汇登记 |
| 国资与上市公司 | 评估、进场交易、审批、信息披露 |
| 环保与安全 | 安全生产责任划分、危废处理、排污许可 |
| 劳动与用工 | 外包 vs 派遣 vs 劳动关系的实质认定风险、社保、竞业限制与补偿 |

#### 3.5.3 程序合规

| 检查点 | 要点 |
|---|---|
| 内部授权 | 是否在分管领导/法务/财务的审批权限内；超权限是否已上报 |
| 关联交易 | 关联方识别、定价公允性、审批与披露 |
| 备案登记 | 不动产租赁备案、抵押登记、商标/专利转让登记、外商投资信息报告 |
| 公证与见证 | 强制执行公证（可直接申请执行，省去诉讼）、重要合同见证 |
| 印章使用登记 | 用章审批与留痕 |

### 3.6 L6 文本质量与形式

> 这一层最容易被轻视，却是「形式审查」的全部内容，也是 Agent 最容易自动化的一层。

| 检查类别 | 检查项 |
|---|---|
| **结构完整性** | 是否有：定义与解释、双方权利义务、价格与支付、交付与验收、知识产权、保密、违约责任、不可抗力、合同变更与解除、通知与送达、转让与分包限制、完整协议条款、可分割性、适用法律与争议解决、附件清单、生效条件与份数 |
| **定义与术语** | 「工作日」vs「日历日」；「包括」是否含「但不限于」；「书面」是否含电子邮件/传真；金额币种是否统一；简称定义后是否一致使用 |
| **一致性** | 条款号引用有效；金额、日期、比例、主体、账户全文一致；中英文版本冲突优先顺序 |
| **冲突条款** | 专用条款 vs 通用条款优先顺序（如使用示范文本，须明确专用条款优先）；正文 vs 附件优先顺序 |
| **签署形式** | 签署页齐全；法定代表人或授权代表签字 + 盖章；**骑缝章**（多页）；日期填写完整；签署主体与首部一致 |
| **附件** | 附件清单与实物一一对应；附件已签署或明确「作为合同不可分割部分」；附件版本号 |
| **电子签署** | 是否为可靠电子签名（《电子签名法》相关要求〔待核〕）；平台存证 |
| **硬伤扫描** | 主体名称错字、金额错位、账号错误、税号错误、条款重复或遗漏、复制粘贴残留（上一份合同的主体名） |
| **版本控制** | 定稿版本唯一、避免多版本同时流转签署；修改处双方签章确认 |

## 5. 分类型专项审查要点

> 通用清单是分母，专项要点是分子。以下按第一版 Agent 覆盖的五类合同 + 四类高频合同展开。

### 5.1 采购合同 / 供应商服务合同

| 专项风险 | 审查要点 |
|---|---|
| 规格锁定不足 | 宁可写厚技术附件，也不要写「符合需方要求」 |
| 付款与验收脱钩 | 验收款必须绑定验收单，而非「到货后」 |
| 质保金退还条件 | 明确触发事件与时限，避免被无限扣留 |
| 供应商锁定 | 独家条款、API/数据格式封闭、备件断供 |
| 交付延期罚则 | 日罚率 + 上限 + 连续超期解除权 |
| 反向责任 | 我方作为采购方的协助义务边界（场地、资料、审批） |
| 框架协议陷阱 | 只约价格不约数量 → 无最低采购量承诺，供方无履约保障 |

### 5.2 销售 / 客户服务合同

| 专项风险 | 审查要点 |
|---|---|
| 验收条款被滥用 | 防止客户以「未验收」无限拖延付款；设置视为验收 |
| 客户单方终止 | 是否约定任意终止权及补偿（未摊销成本、违约金） |
| 无限责任 | 责任上限能否谈下来；至少排除间接损失与可得利益 |
| 服务水平罚则 | SLA 扣款上限、与解除权的关系 |
| 客户资料合规 | 客户提供的数据的权属、使用限制、返还与销毁 |
| 回款保障 | 分期比例、逾期利息、所有权保留、担保 |
| 定制化风险 | 定制需求变更的计价与工期顺延机制 |

### 5.3 房屋租赁合同

| 专项风险 | 审查要点 |
|---|---|
| 出租方权属 | 产权证明、是否共有、是否已抵押、是否二房东（转租授权） |
| 租赁期限 | 《民法典》第 705 条：**不得超过 20 年**，超过部分无效；第 707 条：6 个月以上应书面 |
| 免租期与装修改造 | 装修归属、退租时装修补偿、改造审批、消防验收 |
| 押金 | 金额、退还条件与时限、扣减情形 |
| 租金调整 | 递增机制、物业费与水电费的承担 |
| 转租与分租 | 是否允许、需否书面同意 |
| 优先权 | 优先承租权、承租人优先购买权（《民法典》第 726 条） |
| 解约与违约 | 提前退租的违约金标准、空置损失计算 |
| 备案 | 租赁备案登记义务 |

### 5.4 软件开发 / 技术服务合同

| 专项风险 | 审查要点 |
|---|---|
| 需求基线 | 需求文档作为附件 + 变更控制流程（谁批准、如何计价、工期如何顺延） |
| 里程碑与验收 | 里程碑与付款绑定；验收标准客观化（不写「甲方满意」） |
| 知识产权 | 背景 IP（乙方通用框架/组件）保留 + 前景 IP 归属 + 许可回授 |
| 源码与文档 | 是否交付源码、部署文档、设计文档；第三方开源清单 |
| 人员与连续性 | 关键人员锁定、替换须审批、知识转移义务 |
| 数据安全 | 开发环境数据、测试数据脱敏、访问控制、漏洞修复时限 |
| 质保与运维 | 免费质保期、运维 SLA、报价上限（后续涨价保护） |
| 项目失败处理 | 阶段性交付与结算、终止时的成果与代码移交 |

### 5.5 建设工程 / 分包合同

| 专项风险 | 审查要点 |
|---|---|
| 主体资质 | 施工资质等级与工程规模匹配；禁止挂靠 |
| 招标合规 | 必须招标项目不得规避；合同不得背离中标实质性内容 |
| 转包分包 | 禁止转包与违法分包，明确合法分包范围 |
| 价款与结算 | 计价方式（固定总价/综合单价）、变更签证、结算审计条款、逾期不审视为认可 |
| 工期与索赔 | 开工条件、工期顺延事件、索赔程序与时限（逾期失权条款） |
| 质量与保修 | 保修期（最低法定年限）、质量保证金比例与退还 |
| 安全责任 | 安全生产费用、事故责任划分、保险（建工险、意外险） |
| 优先受偿 | 承包人的建设工程价款优先受偿权（《民法典》第 807 条） |

### 5.6 保密协议（NDA）

必查八项：①保密信息定义（是否含口头信息、是否要求标记）；②例外情形（已公开、独立开发、合法获得）；③保密期限（合作结束后存续几年）；④使用限制（不得用于评估以外目的）；⑤披露例外（法律要求时如何处理：事先通知、协助抗辩）；⑥返还与销毁义务；⑦违约责任与救济（违约金或实际损失 + 禁令救济）；⑧期限（单向 vs 双向）。

### 5.7 借款 / 担保合同

必查：主体资格（非金融机构放贷的效力边界）、利率与费用（不得违反利率管制，超额部分不受保护）、用途限制与提前收回、还款计划与提前还款、担保方式与期间（见 3.4.2）、加速到期条款、抵质押登记、交叉违约条款。

### 5.8 用工相关（外包 / 派遣 / 劳务）

必查：合作性质界定（服务成果导向而非人员管理）、管理与指挥边界（避免事实用工）、结算依据（按成果而非人天）、社保与工伤责任、人员替换权、数据与保密、退出时人员安置。

### 5.9 股权 / 投资框架协议

必查：交易结构（增资/转让）、估值与调整机制（对赌/业绩承诺的效力边界）、交割先决条件、陈述与保证（含重大不利变化条款）、赔偿与托管（escrow）、反稀释、优先权（优先购买、共同出售、领售）、董事会与公司治理、竞业与团队锁定、退出机制（回购、IPO、清算优先）。

## 6. 审查方法与风险判定

### 6.1 三类审查手段（对应 Agent 的三层能力）

| 手段 | 适用检查项 | 特点 | 技术实现 |
|---|---|---|---|
| **确定性规则** | 金额大小写、总价=单价×数量、比例合计、日期逻辑、交叉引用、主体名称一致、附件齐全、必备条款缺失、硬伤扫描（GC-2-22~26、GC-6-01~10） | 结果可复现、可解释、无幻觉 | 结构化抽取 + 规则引擎 / 表达式校验 |
| **库比对** | 与标准模板、企业制度、历史合同、法律知识快照比对（GC-1-xx 资质文件、GC-5-xx 合规、GC-4-07 保证方式等） | 依赖知识底座质量与版本 | 检索 + 版本化快照 + 条款级 diff |
| **语义判断** | 义务平衡性、变更权公平性、责任上限合理性、验收标准客观性、定义歧义（GC-3-xx、GC-4-01~06） | 需要模型理解，存在不确定性与幻觉风险 | LLM + 证据绑定 + Validator + 人工复核 |

**工程原则**：能用规则的不要用模型。模型只做「理解、关联、解释、生成候选意见」，判定与依据必须由规则与原文证据约束。

### 6.2 风险等级判定标准

| 等级 | 判定标准 | 处理要求 | 示例 |
|---|---|---|---|
| **高（P0）** | 可能导致条款无效、重大金额损失、权利丧失、无法救济 | 必须修改，未改不得签署 | 仲裁机构名称错误、无管辖、保证方式未写连带、验收标准主观化、管辖违反专属管辖 |
| **中（P1）** | 影响可执行性、显著增加争议成本或履约不确定性 | 建议修改，不改需书面说明理由 | 付款起算点模糊、质保金退还无期限、责任上限缺例外 |
| **低（P2）** | 文本质量、表述优化、无实质风险 | 可批量修正 | 术语不统一、条文序号错乱、格式问题 |
| **提示（P3）** | 不构成风险，仅提示注意 | 记录备查 | 商业条款对价偏高、非合同义务的商务安排 |

### 6.3 意见口径（三档）

| 档位 | 表述 | 含义 |
|---|---|---|
| **必改** | 「该条款……，导致……，应修改为……」 | 不修改将产生明确法律或商业风险 |
| **建议改** | 「建议调整为……」 | 有利于本方立场，属博弈空间 |
| **提示** | 「请关注……」 | 需业务判断，非法律风险 |

### 6.4 依据引用规范（效力层级）

引用依据必须标明层级，**不得把示范文本、地方口径、案例写成「法律规定」**：

`法律 > 行政法规 > 司法解释 > 部门规章 > 地方性法规/地方司法口径 > 行业示范文本（非强制） > 指导性案例 > 典型案例 > 学理观点`

### 6.5 不确定性的处理规则

1. 拿不准的条款号，标 **〔待核〕** 并给出检索路径，**禁止编造**。
2. 涉及法律版本变动的，须区分**合同签订日对应的法律版本**与**当前审查日有效版本**。
3. 无法从合同原文得到证据的结论，标为「模型推断」或「企业制度判断」，与法律结论分栏呈现。
4. 被推翻的结论要**主动撤回**并说明前次说法有误。

## 8. 审查输出物标准形态

## 附录 D：面向「合同审查 Agent」的工程化映射

把本清单落到 `合同审查Agent需求说明`（v0.4）的架构上：

| 层级 | 覆盖手段 | 需要的底座 | 覆盖率估计 |
|---|---|---|---|
| GC-1-xx 主体与效力 | 库比对（营业执照/资质原件核验）+ 语义（角色错位） | 企业主体信息核验接口、附件解析 | 中（依赖外部核验能力） |
| GC-2-xx 标的与商务 | **确定性规则**为主（22~26）+ 库比对（模板比对）+ 语义（标准客观性） | 条款结构化抽取、数值校验引擎、附件管理 | **高（优先落地）** |
| GC-3-xx 权利义务 | 语义判断为主 | LLM + 证据绑定 + Validator | 中 |
| GC-4-xx 风险与救济 | 语义词条命中（如「连带责任保证」「仲裁委员会」）+ 规则（送达条款是否存在） | 高风险措辞词库、必备条款库、法律知识快照 | **高** |
| GC-5-xx 合规与程序 | 库比对 + 实时核验（高风险/低置信度时） | 法规快照 + 实时核查通道 | 中（受资料时效制约） |
| GC-6-xx 文本与形式 | **确定性规则**可全覆盖 | 文档解析 + 一致性校验 | **高** |

**落地建议顺序**（与需求说明 P0/P1 对齐）：

1. **P0 先做规则可判定的那些**：GC-2-22~26（金额/日期/引用/附件）、GC-6-xx（结构与形式）、GC-4-19~23（争议解决与送达必备条款检查）——不依赖法律知识库，结果可复现，验收门槛清楚。
2. **P1 再做库比对类**：企业模板比对（条款缺失与偏离）、必备条款库、保证方式等高风险措辞命中。
3. **P2 最后做语义类**：义务平衡性、责任上限合理性等需要模型判断的检查项，必须配证据绑定与人工复核。

**每个检查项建议补齐三样东西**（否则无法验收）：判定标准（什么样的文本算命中）、证据要求（需引用原文哪一段）、预期输出（风险等级与建议改法模板）。
