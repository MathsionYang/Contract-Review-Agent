# 通用风险审查清单强化实施记录

日期：2026-09-16

依据：`合同审查内容体系与通用审查清单.md` 第 4 章，六层共 95 项。本文记录实际实现与验收边界，不代表完整法律意见。

## 1. 实施结果

审查主流程为：合同解析 → 事实抽取 → 24 项专项检查 → 95 项通用清单 → 可选模型复核 → 人工复核与导出校验。

- 95 项均保留编号、层级、判据、默认等级、适用条件、实际方法、状态、证据要求和检查范围。
- 加强付款起算、主观付款条件、前置单据、税票与账户、交付、验收救济、知识产权、数据处理、人员、违约、解除、送达和文本质量检查。
- 主体登记、授权、印章、审批、资质、签署与监管核验不能仅靠合同自述通过，各项保存具体所需材料。
- 保证方式、违约金比例等商业偏好不自动等同于强制法律要求；文本命中只能形成候选，模型不能自证风险已经核验。
- 专项检查与通用清单存在映射，分开统计，不能将 24 + 95 解释为 119 项独立风险。

清单目录版本为 `GC-1.0-2026-09-16`。该版本标识判据目录，不表示所有检查方法已经自动化。

## 2. 工作区与复核

右侧结果区域提供“风险”和“通用清单”两个视图。清单可按 L1-L6、状态、编号或文本筛选；展开后显示判据、检查理由、材料要求、原文引用和关联风险。

人工复核单独保存在检查项的 `human_review` 中：

| 字段 | 含义 |
| --- | --- |
| `outcome` | `pass`、`not_applicable` 或 `unverifiable` |
| `reviewer` | 复核人 |
| `evidence` | 材料编号、来源或核验记录引用 |
| `note` | 核验过程与结论说明 |
| `reviewed_at` | 复核时间 |
| `file_version_id` / `document_hash` | 绑定当前合同版本与哈希 |
| `catalog_version` | 绑定清单目录版本 |

每次保存产生独立审查版本和 `humanRevisions` 记录，不覆盖自动状态及统计。人工记录属于人员声明，不等于系统已经连接登记机关或验证材料真实性。重新运行审查会重建清单，不能沿用旧的人工结论。

## 3. 定位与计算修正

- 缺失引文、无法匹配或存在多处歧义时保持待定位，不使用合同首页或当前页开头作为风险证据。
- 引文匹配允许空白和换行差异，但返回原始文本、块内范围与文本哈希；条款号从实际匹配位置确定。
- 同名但位于不同条款的风险不再仅按标题合并。
- DOCX 显示逻辑块定位，通过逻辑页导航，不伪造物理页码。`V3.0` 等产品版本不再被解析为条款号。
- PDF 明细核对取消数字组合凑合计，限定为完整连续行重建，并验证数量乘单价、行金额和总价。不能可靠重建的表格不输出通过。

## 4. 模型与导出

模型收到适用项的完整 `check_plan`，内容预算包含清单、事实、检索依据、合同文本和输出预留。预算沿用项目的 Token 估算器，并非模型专用精确分词。

删节记录在 `model_context`，包含预算、估算用量、参与检查编号、删节页码、省略事实数和依据数。合同删节返回 `MODEL_CONTEXT_TRUNCATED` 并维持部分完成；检查计划和最小原文无法容纳时返回 `MODEL_CONTEXT_INSUFFICIENT`，不发送超长请求。当前尚未实现跨批次全量语义审查。

导出校验增加：

- `CHECKLIST_INVALID`：目录版本、95 项编号唯一性、等级或状态不完整。
- `CHECKLIST_COVERAGE_INVALID`：逐项结果与覆盖统计不一致。
- `CHECKLIST_REVIEW_REQUIRED`：关键待核验/未执行项没有绑定当前版本的完整人工记录。
- `HIGH_RISK_LOCATION_UNRESOLVED`：高风险位置未解析；填写页码不能绕过显式待定位状态。

DOCX 块锚点经原文哈希和范围核验可通过定位校验。清单人工复核不会豁免既有风险证据、风险人工确认及法律快照门禁。

JSON 导出增加完整清单、专项结果及统计、事实、解析警告、执行摘要和模型上下文记录。DOCX/PDF/XLSX 仍为既有风险报告布局，尚未新增 95 项逐项清单附表。

## 5. 真实合同回归

输入为 `data/软件采购合同.docx` 与同名 PDF；未配置外部分析模型、外部知识或补充附件。`风险清单.md` 不参与运行时推理。

| 集合 | 总项数 | 已执行 | 通过 | 冲突 | 缺失 | 不可验证 | 未触发适用条件 | 跳过 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 专项检查 | 24 | 24 | 0 | 19 | 5 | 0 | 0 | 0 |
| 通用清单 | 95 | 30 | 1 | 11 | 18 | 53 | 12 | 0 |

两种格式逐项状态一致，均输出 42 条候选风险，31 项高风险通用检查待核验，任务为 `partial`。候选数量不能用于宣称对 26 项真实问题的召回率，尚需独立逐项对照和误报评估。

DOCX 有 157 个证据块、54 条事实；PDF 有 7 个页级块、52 条事实。事实粒度与地址分段仍存在差异，不能声称解析事实完全一致。

- `npm test`：96 项通过，无失败或跳过。
- `npm run build`：通过。
- 本轮 10 个后端模块 `node --check`：通过。

- 组件服务端渲染测试确认 95 项、复核表单、原文定位入口与双视图结构存在；没有替代真实浏览器交互验收。
- computer-use 浏览器工具返回无可用浏览器，因此没有完成桌面/窄屏截图检查。没有调用真实外部模型 API。

使用新结果需重启桌面端，并重新运行审查。旧解析结果没有证据块或条款号受旧解析器影响时，应重新导入原合同。既有模型配置按独立 `configId` 保留，同名配置并存的持久化回归继续通过；本次未改动真实凭据或用户审查状态。

本地界面预览：`http://127.0.0.1:5180/?view=review`。浏览器预览不具备 Electron 文件导入、模型执行和正式导出能力。

## 7. 保留边界

当前不是“95 项均由模型自动核验”的系统。部分专项检测仍依赖既有合同条款结构，需继续拓展不同编号、表格布局与行业样本；关键词筛查仍需要上下文复核。OCR、可靠物理分页、跨附件事实图、向量检索、精确 Token 计费和完整 26 项缺陷评分均未在本轮交付。
