# 导出策略调整实施记录

更新日期：2026-09-17

## 两级导出

界面默认选择草稿，可在系统设置中修改默认模式和格式。底层 API 未指定模式时仍按正式报告校验，防止旧调用方意外放宽校验。

| 检查结果 | 草稿 | 正式报告 |
| --- | --- | --- |
| 高风险待人工复核、证据未核实、定位未确认 | 告警并附待核验事项 | 阻断 |
| 法律快照未发布、来源待核验、关键清单待复核 | 告警并附待核验事项 | 阻断 |
| 审查部分完成或失败、OCR 文本不可用 | 告警并说明局限 | 阻断 |
| 疑似密钥、必填结构损坏、覆盖统计不一致、文件版本错误 | 阻断 | 阻断 |
| 无格式、不支持的格式、无效模式、审查或对话运行中 | 阻断 | 阻断 |

草稿不是强制忽略校验。Validator、主进程和文件生成器均接收并验证模式；前端设置不能关闭基础安全校验。原有 `forceValidator` 设置不再作为可关闭校验的界面选项。

## 文件和记录

- DOCX、PDF、XLSX、JSON 的文件名区分草稿和正式报告。
- DOCX 使用标题、声明和重复页眉标记草稿；PDF 每页保留 `DRAFT - NOT FINAL`；XLSX 在风险表标题及导出校验表注明草稿；JSON 保存 `export_mode`、`report_status`、完整校验结果。
- 四种草稿均保留待核验事项、风险标识、问题及处理建议。缺失项不伪造合同原文或具体条款，DOCX 逻辑块不伪装成物理页码。
- 导出记录中的 `status: completed` 仅表示文件生成完成；是否正式报告由 `report_status` 和 `export_mode` 表示。另记录策略版本、告警代码和正式报告就绪状态。
- 导出不把风险改成已接受、不把证据改成 verified，也不把 partial 任务改成完成；具备正式导出条件的草稿仍然保留草稿身份。
- 取消目录选择不增加导出记录。删除过的任务不能从旧页面导出。

## 定位兼容修复

事实抽取复用原文引用解析器，保存块内字符范围、逻辑页和哈希。历史 DOCX 引用缺少字符范围时，只接受哈希一致且引用在同一块内唯一出现的情况；错误范围、重复引文或文本已变化仍不通过正式校验。

已删除或误报且结论为 rejected 的候选，不再作为待确认风险阻断正式报告；未明确驳回的风险仍继续校验。

## 验证

覆盖正式和草稿校验、硬阻断、四种实际文件、PDF 跨页标识及文本边界、主进程模式传递、取消导出、删除后阻断、组件渲染和真实合同 DOCX/PDF 回归。专用 Word 渲染环境和桌面实际点击验证不在当前环境的已验证范围内。
