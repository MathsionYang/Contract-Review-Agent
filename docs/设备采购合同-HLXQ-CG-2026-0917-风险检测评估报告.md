## 5. 关键准确性问题

### 5.1 严重风险被降级

1. `check_GC-4-19` 将仲裁与诉讼并存标为 high，但基准 D-04 为 P0；这是会改变审批动作的定级错误。
2. `check_GC-4-05` 将责任上限问题标为 medium，且无 13.5 引文；D-03 是 P0。
3. `check_GC-2-05` 只提示税率缺失，未识别含税/不含税冲突；D-06 是 P0。
4. 售后 SLA、IP、数据、不可抗力等 P1 风险均被输出为 medium 或 unresolved，审批摘要容易被 21 条 medium 淹没。

### 5.2 条款与风险不对应

- 21/27 条风险 `location_status=unresolved`，没有 `quote`、`source_refs` 或具体条款号；这类对象不能直接证明合同存在相应问题。
- `GC-4-12` 声称未检出不可抗力通知，但合同第 14.3 条明确约定通知；问题应改为“免证明材料及后果不充分”，而不是“通知缺失”。
- `GC-3-07` 声称未检出不侵权保证，但合同第 2.4 条已有“合法生产或有权处分、不存在权利瑕疵”的基础保证；系统应报告“抗辩、费用和赔偿机制缺失”，不能把已有保证当作不存在。
- `GC-4-05` 声称未检出责任上限，但合同第 13.5 条明确写有 5% 上限；这是事实存在性判断错误。
- `GC-2-25` 声称 1.4 不存在，而合同首部/第一条已有 1.4；同时没有准确抓住 7.5→9.1 和 5.5→6.4 两条引用问题。

### 5.3 重复、泛化和结果状态混用

- D-02 被拆成两个风险对象，导致数量看起来增加，但没有合并为一个带“费率、基数、封顶、重复救济”关系图的风险。
- 27/27 条风险均为 `pending_review`；确认风险、待核验项、规则提示和“缺少可选条款”没有分层。
- “律师费与保全费”“关键人员”“商标许可”等项目缺少基准缺陷对应关系，至少应先标为适用性检查或建议项，不能与已证实 P0/P1 同层展示。

## 6. 根因判断

### P0：规则与结果状态设计不安全

- 缺少“证据门槛”：没有原文引用的缺失项仍进入风险列表。
- 缺少“风险状态机”：`confirmed`、`needs_verification`、`info`、`not_applicable` 未严格隔离。
- 严重度没有由确定性规则覆盖模型判断；因此已明确的 P0 被降级为 medium/high。
- 缺少跨条款风险图，金额、日期、责任上限、税务、交付与解除被当作独立关键词问题。

### P1：事实模型不够完整

当前 essential 抽取重点是 money、ratio、duration、obligation、penalty。对于本样本，仍需把以下事实作为一等公民：

- 主体字段：统一社会信用代码、法定代表人、住所、账户户名；
- 条款结构：条款号、标题、重复编号、引用目标、附件实体；
- 日期与时序：签署日、生效日、交货日、付款触发日、质保起算日；
- 权利义务要素：许可期限、解除权、责任例外、保密方向、数据用途、通知方式；
- 表格关系：数量、单价、金额、合计、付款比例和分期金额的可计算关联。

### P1：缺失条款检查没有“适用性和邻近证据”

“未检出完整约定”只能说明某个要素可能缺失，不能直接说明合同存在风险。必须同时记录：适用依据、扫描范围、最近条款、已发现要素、缺失要素和是否需要附件。

### P2：抽取拒绝结果没有向下游正确传播

11 条候选被拒绝本身是保护机制，但如果下游只看到“没有该事实”，就会把“抽取失败”“合同缺失”“合同已存在但要素不足”混为一谈。应保存事实的 `extraction_status` 与拒绝原因，并让规则区分三种状态。

## 7. 功能设计加强方案

### P0 立即加强

1. **风险证据闸门**
   - confirmed 风险必须具备 `clause_no + quote + source_refs + location_status=resolved`。
   - 无法定位的结果只能进入 `pending_verification`，不能计入正式风险数量和严重度统计。
   - 跨条款风险必须列出全部相关条款，不能只挂第一条命中条款。

2. **确定性严重度覆盖**
   - 建立 `ground_truth/policy severity resolver`：含税/不含税并存、仲裁诉讼并存、核心责任 5% 封顶、全额预付等规则一旦证据满足，至少固定为 P0。
   - 模型只能补充分析，不能把确定性规则降级；若存在例外（保函、特批、合同类型），必须显示例外证据。

3. **风险状态机和导出门禁**
   - 分离 `confirmed`、`needs_verification`、`supplementary_check`、`not_applicable`、`rule_note`。
   - 正式导出禁止把 unresolved/pending 当成已确认风险；草稿导出必须显示确认率、定位率和未覆盖基准项。

4. **跨条款关系引擎**
   - 金额图：大写/小写、明细合计、分期金额、比例合计、合同总价统一计算并保留计算式。
   - 时间图：签署日→生效日→付款→交货→安装→验收→质保，检测早于签署、期限冲突和单位冲突。
   - 责任图：双方主体、费率、计算基数、封顶、重复救济、解除权、责任例外统一比较。
   - 引用图：条款号唯一性、引用存在性、引用语义是否匹配、附件是否真实随附。

### P1 近期加强

1. **完整合同结构抽取**：新增 party/date/clause/reference/condition/license/data_use/confidentiality/attachment 等事实类型，并将表格单元格与行列语义保存为结构化字段。
2. **条款缺失检查改为“要素矩阵”**：每个检查项输出 `found_elements / missing_elements / applicability / evidence_window / required_attachment`，不再只输出一句“约定要素待补齐”。
3. **风险合并与去重**：以“风险主题 + 条款集合 + 计算关系”聚类；D-02 只能形成一个主风险，子项显示费率、基数、封顶和重复计罚。
4. **主体和形式校验**：内置统一社会信用代码 18 位及校验位、法定代表人/住所/签字栏、货币和日期格式校验。
5. **附件实体校验**：将合同中列举的附件与实际导入文件、版本、哈希逐一比对；附件未导入时引用具体附件名和触发条款。
6. **法律/制度依据分层**：区分法律依据、企业制度、模型建议；没有可靠来源时不得生成看似确定的法律结论。

### P2 体验和治理加强

1. 在对话审核中展示“原文条款→抽取事实→规则计算→风险结论”的链路，每个风险可展开查看被采用和被拒绝的事实。
2. 增加基准回归集，固定覆盖 D-01 至 D-40，并将召回率、P0 召回、定级准确率、定位率、误报率作为版本门禁。
3. 提供按“已确认 / 待核验 / 未覆盖 / 规则提示”筛选和导出，避免审批人只看到一个混合风险列表。
4. 记录每次规则、模型、提示词、解析器版本和缓存命中状态，保证同一合同可重现。

当前最应该先改的不是继续增加模型提示词，而是先建立“证据闸门 + 风险状态机 + 跨条款确定性规则”。在这三项完成前，继续扩大语义模型或知识库只会增加待核验条目，不能稳定提高审批准确性。

- 已确认且可直接复核：D-05；
- 有价值但需要重算/补证据：D-02、D-03、D-04、D-06、D-10、D-11、D-13、D-18、D-19、D-20、D-25、D-28、D-32、D-33、D-35、D-36；
- 其余结果应先按待核验或补充检查处理，不应作为已经确认的合同风险。

报告结论：**当前助手具备“发现部分线索”的能力，但还不具备对该合同进行完整、准确、可直接审批的风险审查能力。**
