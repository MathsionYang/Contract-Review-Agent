# 条款抽取与向量检索模型接入说明

更新日期：2026-09-17

## 本次变更

原有审查流程只调用 analysis 模型，extraction、embedding 等角色只有配置记录。本次接入 extraction 和 embedding，并保留原有本地检查与风险流式更新。

| 角色 | 执行行为 | 失败或缺少配置时 |
| --- | --- | --- |
| extraction | 分批读取合同原文块，调用模型抽取结构化事实，校验引文、定位及数值后合并 | 保留规则事实及已校验的模型事实；调用失败标记降级 |
| embedding | 对当前选用的知识条款分块生成向量，进行关键词与向量混合检索 | 继续关键词检索；调用失败标记降级 |
| analysis | 使用合同、事实、检查计划和检索依据生成待核验风险 | 保留本地检查和已接收完整的模型风险 |
| rerank / vision | 尚未接入 | 明确显示“尚未接入执行”，不伪造调用成功 |

完整审查顺序为：合同解析、条款事实抽取、确定性检查、知识检索、语义风险分析、结果校验、保存。

对话审查也使用混合检索。关闭“知识依据”时不调用向量模型，检索阶段仍支持取消。首次风险对象完整到达时立即更新风险清单，随后补充检索依据，不等待全部风险返回。

## 模型配置

1. 重启 Electron 桌面端，使新增主进程接口和 preload 生效。仅刷新旧窗口不能加载新的主进程代码。
2. 分别保存 analysis、extraction、embedding 角色的模型配置。现有多个模型不会被合并或覆盖，仍按配置 ID 选择本次任务使用的模型。
3. 点击模型行的“测试连接”图标。测试会发送最小测试文本，不发送当前合同正文。通过后手动启用。
4. 选择企业制度、规则或绑定已发布的法律快照，再重新执行审查。旧审查结果不会自动重跑。

当前协议为 OpenAI 兼容协议：

- analysis、extraction 使用 `/chat/completions`，要求模型能返回结构化 JSON。
- embedding 使用 `/embeddings`，请求体包含 `model`、`input` 文本数组和 `encoding_format: float`，不包含聊天参数。
- API 地址可填写服务基础地址，例如 `https://your-model-service.example/v1`，也可填写完整的上述接口地址。
- 向量模型必须是服务商实际提供的 embedding 模型。不能因为某个聊天模型能调用，就假定同一模型也支持向量接口。
- 向量响应要求 `data` 数组，每项包含唯一的 `index` 和非零、有限数值组成的 `embedding`；数量、维度必须一致。
- API Key 仍仅在主进程中读取；审查执行摘要不记录接口地址或凭据。浏览器预览没有本机模型调用能力，不会将字段检查伪装成连接测试。

旧版本的“配置校验通过”只代表字段检查。旧配置保留兼容性，但界面显示“仅字段已校验”，建议重新测试连接。修改配置后，旧测试结果失效。

## 抽取与原文校验

模型抽取包括金额、比例、期限、主体、义务、罚则、条件、日期和引用等事实。每条候选必须带原文块 ID、连续原文引文及条款号。

- 引文必须在本批次提供的原文范围内唯一定位，不能使用模型自报的页码或虚构原文。
- 同一块内出现多次相同引文时，必须通过字符偏移消除歧义。
- 条款号从原文或解析块推导，模型提供了冲突编号时拒绝该事实。
- 金额、比例和期限重新从引文验证数值；无法可靠验证时不进入计算输入。
- 与本地规则已提取的事实按类型、条款、数值及原文范围去重，避免重复累计付款比例或金额。
- DOCX 使用真实逻辑块和逻辑页定位，不伪造物理页码。
- 模型事实保留 `origin: model` 和 `verification_status: anchored_candidate`，原文匹配不等于业务含义或法律结论已经确认。

长合同按上下文预算和文本大小分批，切分处保留重叠。失败时记录完成批次数，保留已完成结果；未处理内容不能宣称已完成语义抽取。

## 向量索引与检索

知识在首次需要检索时分块生成向量。向量数值缓存在应用数据目录的 `cache/embeddings` 中，检索时按当前选用来源组装内存索引。

- 缓存键包含模型配置、接口、模型标识、版本、测试时间及分块文本的哈希；原文和 API Key 不写入该缓存文件。
- 未变化的知识块可复用向量。修改知识内容、模型版本或重新测试模型后，相应缓存自动失效。
- 删除、取消选用或不再绑定的知识不会出现在检索索引中。历史数值缓存不会使已删除的知识重新被召回。
- 使用余弦相似度与关键词检索，通过倒数排名融合合并结果。当前向量候选阈值为 0.45，最多参与融合的向量、关键词候选各 30 条；阈值不是法律适用性的判断标准。
- 向量响应异常或与索引维度不一致时停止本次流程的后续向量请求，降级关键词检索，不静默伪造成功。
- 混合检索结果保持候选状态，并保留来源、条款和原文片段。高相似度不代表依据适用，也不自动确认风险。
- 审查模型的上下文分别为事实和检索依据预留预算，避免事实过多将依据全部挤掉。

向量数据也是业务衍生数据，应按本机知识库的访问权限和备份政策管理。此实现为桌面规模的本地缓存与内存相似度检索，不是独立的大规模向量数据库。

## 执行记录

审查结果中的 `execution_summary` 记录实际模型、状态、调用次数、耗时及必要错误信息；抽取另记录接纳、拒绝、去重数量与批次进度，向量阶段记录分块数、缓存命中和查询数。调用次数按网关调用计，服务商重试次数另由网关记录。

“查看配置”面板显示实际执行状态，能力配置中的“已启用”不再显示为“运行中”。对话上下文快照也保存检索摘要，回答下方显示混合检索或降级状态。

### 对话区过程展示

“对话审核”同时展示完整审查任务的条款抽取与语义分析过程，不需要先发送一条对话消息：

- 条款抽取：显示当前批次、完成批次数、用时、当前原文片段、规则事实数量、模型新增数量和合计；批次返回后更新最近 5 条通过原文校验的模型事实，以及去重、拒绝数量。抽取接口按批次返回，不会将未完成的响应伪装成已提取事实。
- 语义分析：区分准备上下文、等待模型响应、接收并整理风险、完成或失败；完整风险对象到达时更新候选数量及最近 5 条风险。未完成的 JSON 和模型内部推理不会显示，也不会编造语义分析完成百分比。
- 两类过程均支持展开、收起；阶段结束后自动收起详细内容，保留摘要和异常信息。新任务重新生成过程摘要，旧任务事件不能覆盖本次状态。
- 过程摘要保存在该审查版本的 `execution_summary`，不是聊天消息，不会被当作用户指令或塞入最近对话。原有对话保持不变。

### 对话上下文范围

原“模型只会使用已勾选的上下文”提示已替换为当前可用上下文列表。勾选项只控制对话请求是否加入当前页、选区、当前风险、知识依据和企业记忆；必要合同信息及最近对话仍会进入上下文。具体内容是否纳入还取决于有无相关数据和上下文预算。

这不是模型能力限制，也不限制整份合同自动审查的输入流程。对话默认不是自动发送整份合同；完整审查由审查任务执行，仍受模型窗口和预算约束。分析过程中如有原文删节，会明确显示未覆盖全部内容。

状态含义：

- `completed`：本阶段协议调用和处理完成，不代表模型结果已人工确认。
- `partial`：存在被拒绝的抽取事实，需要核对。
- `degraded`：配置的模型调用或校验失败，已使用本地降级路径。
- `not_configured`：没有可用模型，未尝试该角色的远程调用。
- `skipped`：没有当前可检索的知识，不发空请求。
- `not_integrated`：角色尚未接入实际执行流程。

## 验证与限制

回归验证包括：三个模型角色的本地 HTTP 协议调用、原文锚定、伪造事实拒绝、重复事实去重、长文分批、缓存复用及失效、删除隔离、异常降级、对话取消、连接测试 IPC、界面状态、逐条风险更新及生产构建。

```powershell
npm test
npm run build
```

自动验证使用模拟响应和本地 HTTP 测试服务，没有读取或使用用户 API Key 请求外部服务。服务商模型是否可用、抽取质量和实际召回质量，仍需以桌面端真实连接测试及代表性合同验证。

本次不包含 OCR、视觉模型、重排序模型或官方法律网页适配器。扫描 PDF 没有文本层时仍需要 OCR；既有部分专项金额检查仍依赖约定条款号，本次没有将其全部泛化。模型接入不保证消除所有“输入不足”提示，也不替代人工法律复核。
