# 腾讯电子签合同 AI 助手（精简教学范本）

本文是生产级 Skill `tencent-esign-contract` 的结构化提炼，用于回答一个问题：**一个能稳定跑起来的 Skill，骨架由哪几层构成、每层为什么这么写。**阅读顺序即落地顺序，每节末尾的设计要点可直接迁移到你自己的技能。

## 一、frontmatter：技能的身份契约

```yaml
name: tencent-esign-contract          # 唯一标识，必须与目录名一致
description: "…八大能力 + 触发词…"      # 唯一的路由依据，见下
metadata:
  openclaw:
    requires:
      bins: ["python3"]               # 前置依赖，缺失即报错，不静默降级
    category: "tencent"
    tokenUrl: "https://qian.tencent.com"
  version: "1.3.0"                    # 技能自身版本，独立于宿主插件版本
  homepage: "https://qian.tencent.com/"
```

> **设计要点（description 三写法）**
> 1. 用**用户会说的话**写，不用技能会做的事写——"帮我看看这份合同有没有坑"比 "review contract" 更容易命中。
> 2. **枚举意图 + 覆盖隐式表达**——除八类显式意图外，补上"用户只丢来一个文件路径""这份合同"等模糊说法。
> 3. **预置歧义优先级**——"审查列表"必须先于"审查"被匹配，否则"看审查记录"会被误路由成一次审查任务并消耗额度。

## 二、角色定位：你是调度器，不是执行者

| 行为边界 | 说明 |
|---|---|
| 文件只上传不读取 | 唯一允许：`ls` 确认存在、校验扩展名 |
| 专业判断交云端 | 审查/对比/起草由云端引擎完成，本地复现会产生错误结论 |
| 预渲染内容原样输出 | 脚本返回的 `_` 前缀字段直接复制给用户，不改写、不截断、不重排版 |
| 导出文件自动下载 | 脚本下载到技能目录 `downloads/`，迁移到工作区后再展示路径 |
| 严格按指南执行 | 读取 `references/xxx.md` 后按阶段执行，不跳步、不自行发挥 |

> **设计要点**：把"模型不该做的事"写成表格，比写成段落有效得多。这条边界直接决定结果可信度——一旦允许模型自己"分析合同"，输出就从确定的服务响应退化为概率性编造。**任何调用外部专业引擎的技能，都应显式禁用本地推断。**

## 三、处理流程

```
收到用户消息 → 意图识别（查路由表）
  ├─ 命中业务意图 → 鉴权 → 按路由表指定方式执行
  ├─ 仅命中产品引导词 → 回复引导模板
  └─ 都不命中 → 通用对话
```

同时命中"业务意图"和"产品引导词"时，优先执行业务流程，引导内容附在结尾。

## 四、意图路由表（命中第一个即停）

| # | 意图 | 匹配词（节选） | 执行动作 |
|---|---|---|---|
| 1 | 审查列表 | 审查记录/审查历史/之前审查的 | 鉴权 → `review-list-url` |
| 2 | 对比列表 | 对比记录/对比历史/之前对比的 | 鉴权 → `compare-list-url` |
| 3 | 合同起草 | 起草/写/拟/生成/草拟 + 合同/协议 | 读 `draft_guide.md` → 执行 |
| 4 | 合同签署 | 签署/发起/帮我签/怎么签/发给对方 | 读 `create_flow_guide.md` → 执行 |
| 5 | 合同审查 | 审查/检查/有没有坑/条款有问题吗 | 读 `review_guide.md` → 上传→云端→展示 |
| 6 | 合同对比 | 对比/差异/两版不同/改了什么 | 读 `compare_guide.md` → 上传→云端→展示 |
| 7 | 合同查看 | 我的合同/签完在哪看/合同列表 | 读 `create_flow_guide.md`「合同查看」 |
| 8 | 法条检索 | 查法条/法律依据/法律怎么规定 | 读 `law_search_guide.md` → 执行 |

歧义处理规则：列表类优先于任务类；用户只说"历史记录"时反问答的是审查还是对比；"这份合同有没有问题"归审查，不进通用问答。

> **设计要点**：路由表是 Skill 的"CPU 指令集"。它必须满足三点——**优先级有序**（第 1 行先于第 5 行判定）、**匹配词取自口语**（不是功能名）、**每行都指向一个明确的下一步**（读哪份指南或调哪条命令）。歧义规则单独成段，因为路由表本身无法表达"谁优先于谁"。

## 五、鉴权：把一次性的麻烦变成永久无感

| 场景 | 动作 | 用户感知 |
|---|---|---|
| 仅打招呼/问能力 | 不做任何 token 操作 | 不被索要 |
| 业务任务 + 已有有效 token | 直接发起，跳过重复验证 | 完全无感 |
| 业务任务 + 无 token | 引导获取 → 校验 → 自动写入 → 续跑业务 | 仅一次引导 |
| API 返回鉴权错误 | 提示重新获取 → 覆盖旧值 → 续跑 | 显式提示（罕见） |
| 用户明确撤销 | 删除令牌文件 | 显式提示 |

```
python3 scripts/tencent_esign.py auth-check      # success:true 则直接开工
python3 scripts/tencent_esign.py auth-validate <token>   # 校验通过后自动持久化
```

> **设计要点**：凭证持久化到 `~/.xxx-token`（权限 600），跨会话、跨任务复用，**不走环境变量**——环境变量存在旧值遮蔽、跨会话丢失、易被误打印三类问题。同时明确"何时不该打扰用户"，避免把鉴权提示变成每次对话的开场白。

## 六、资产分层：Hub-and-Spoke

| 层 | 文件 | 加载时机 |
|---|---|---|
| 入口（Hub） | `SKILL.md`，约 240 行 | 每次命中技能即加载 |
| 指南（Spoke） | `references/draft\|review\|compare\|law_search\|create_flow\|common_guide.md` | 命中对应意图时按需读取 |
| 执行 | `scripts/tencent_esign.py` 单文件 CLI | 需要调接口时执行 |
| 产物 | `downloads/` | 脚本自动落盘 |

> **设计要点**：入口只放**强制规则、鉴权、流程、话术模板**，实现细节（JSON 结构、解析步骤、展示规则）全部下沉到 `references/`。动机是注意力经济——把所有细节塞进入口会稀释关键指令，弱模型会开始漏步；**按需加载让每一次上下文里只有当前任务需要的那部分**。

## 七、运行环境

- 命令从技能根目录执行：`python3 scripts/tencent_esign.py <command>`，不可用时回退 `python`
- Token 从 `~/.esign-token` 读取，由 `auth-save` / `auth-validate` 写入
- Web 预览链接有效期 3 小时；导出文件自动落盘，仅在失败时回退为 20 分钟下载链接
- 调用接口时传 `SkillPlatformName`，用于平台来源统计，非法值自动归一为"其它"

## 八、可迁移清单（写你自己的 Skill 时逐条对照）

1. `name` 与目录名严格一致，`description` 里写满用户口语触发词。
2. 显式写清**不该做什么**，尤其是"不要本地推断专业结论"。
3. 路由表优先级有序，匹配词取自口语，每行都有明确下一步。
4. 长内容下沉到 `references/`，入口只留强制规则。
5. 鉴权做成一次性引导 + 永久复用，并规定"何时不该打扰用户"。
6. 所有产出物明确**落盘位置**与**有效期**，不留在模型上下文里。
7. 同一份规则只写一次（如"文件只上传不读取"只在边界表定义，其他处引用）。
8. 把有副作用的操作（扣额度、建任务、发文件）标记为**不可自动重试**。
